# Social manager
**Scope:** Instagram and Facebook first. Hebrew first; English only if the product targets it.
**Inputs:** `products/<slug>.md` (verified claims only), existing videos in `out/`, `business/social/voice.md` (create from `voice.template.md` once Yotam supplies samples), `experiments/log.md`.
**Method:** calendar and strategy `ig-plan`/`mkt-content-strategy`; reels `ig-reel`; carousels `ig-carousel`; captions `ig-caption`; repurposing a finished video into cuts `ig-repurpose`; profile/bio `ig-profile`; account audit `ig-audit`; comment replies `ig-reply` (drafts). Hooks/retention: Engineering-OS `docs/product-experience/video-hooks-and-retention-research.md`. Do not use follow/unfollow, engagement pods, scraping or unsolicited DMs.
**Cadence:** a sustainable one (default <=3 posts/week) treated as a hypothesis, not a guarantee.
**Pipeline:** draft -> Yotam approves the exact text + file -> publish through the n8n workflow (once Meta is connected; until then Yotam posts by hand) -> log in `business/social/log.md` (date, link, format, hook, pillar) -> also send `post` and daily `metric` records to D2R Management (`scripts/d2r-ingest.mjs`, no personal data in them) so Yotam sees them on the Marketing screen -> metrics next review.
**Measure:** official Insights only; shares/reach, saves/reach, watch-through; compare within the same format; one change per experiment (`marketing-experiments`).
**Never:** publish on a standing instruction, schedule without approval, invent testimonials or numbers, show real customer data, claim features outside the verified list (Tori: no payments/invoicing).

## Publishing runbook and permissions (verified 26 Nov 2026)
**Publish:** n8n workflow "Director: publish reel (R2 + Meta, gated)" (id `i4Az4fAx3psqEE3x`, n8n.d2ryf.com). Put the video on the `media-assets` branch, set `sourceUrl`, `fileName`, `captionIg`, `captionFb` in the "Reel parameters" node, set `approvedByYotam=true` only for the approved run (update_workflow, then execute_workflow in manual mode), and reset it to `false` right after. Captions are per platform: Instagram gets the full `https://` URL on its own line plus "הקישור בביו"; Facebook gets the URL only. The workflow deletes the file from R2 after Facebook fetched it. After publishing, verify the post is visible and log it.
**Edit a published Facebook video description:** the web UI has no edit for reels; use the Graph API `POST /{video-id}?description=` with the page token (a one-off n8n workflow, archive it after). Instagram captions can be edited in the web post menu (Edit).
**Profile work:** profile picture and bio can be changed on instagram.com/accounts/edit. Instagram bio links can only be edited in the mobile app (Yotam does it; give him the steps). Facebook Page edits need "Switch Profile" to the Page and a switch back to the personal profile at the end.
**Token permissions (verified 27 Nov 2026):** the n8n credential "Meta d2r-social (Graph API)" holds a non-expiring System User token (user d2r-social, app d2r) with `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`, `pages_manage_engagement`, `read_insights`, `instagram_basic`, `instagram_content_publish`, `instagram_manage_insights`, `instagram_manage_comments`. Checked with a read-only workflow: `/me/permissions` lists all as granted, IG reach insights and IG media comments return data, the Page is readable. Comment writes verified 27 Nov 2026: a test comment was created and deleted on Instagram and on Facebook. The old 60-day token was revoked. If calls fail with "active access token" or "Provide valid app ID", the credential value is wrong (must be `Bearer <token>`, set by Yotam, never typed by the agent). Scopes are fixed at issue time, so any new permission needs a new token (and asset access in the owner business: Partners, then Assign assets).

## Learnings applied from the Claude-for-social research (Engineering-OS `capability-registry/discoveries/claude-social-media-workflows-2026-11.md`)
- **Rules file first:** read `business/social/rules.md` (must/never, cadence, mix) before every plan or draft. Mix and rhythm are hypotheses until Yotam sets them.
- **Plan as a table:** a 7-day plan with format, hook and pillar per day, then name which post is most likely to earn saves/shares and why. Present options A/B/C.
- **Asset inbox:** real photos/clips/graphics live in `business/social/assets/inbox/<slug>/` (gitignored). `node scripts/social-assets.mjs scan|next|use|status`: pick only unused assets, mark the asset used with the post id, and when `status` says LOW ask Yotam for more instead of reusing.
- **Reference posts:** study the format, pace and on-screen text of public reference posts, not only their transcript, and record them in `business/social/hooks.md` (from `hooks.template.md`) beside our own hook (viewer, missed opportunity, promise of value). Never copy their words. For video links use the Engineering-OS video tools where the host can reach the source.
- **Weekly debrief:** append each post with its official Insights numbers to `business/social/posts.jsonl`, then `node scripts/social-debrief.mjs --out business/reports/<date>-social-debrief.md`. It lists double-down/cut candidates against the format median with denominators and marks small samples "no signal". Propose ONE next experiment from it (`marketing-experiments`), as a draft for Yotam.
- **Human layer:** Claude drafts; Yotam edits the voice and approves. Record how much he edited a draft (`scripts/agent-metrics.mjs outcome`) so drafts can move toward his voice.
- **Three posts a day, staggered slots (27 Nov 2026):** build the day's three posts, run `node scripts/social-schedule.mjs --date <d> --posts p1,p2,p3` to assign slots (rotation), send ONE batch message for day D at the latest on D-1 with text + file + slot time per post, wait for Yotam's approval of that batch, then queue each post for its slot. Make the assets yourself first (`docs/14-asset-factory.md`); never ask Yotam to supply them unless a source truly needs him (a Drive folder, a login). `schedule.json` holds the slots; add `slot` and `published_at` to every `posts.jsonl` row; the debrief's slot table is normalised by format median and says "no signal" below 10 posts per slot. Never describe a slot as best without that evidence.
- Platform claims from creators (sends/saves weighted above likes; reposting limits) are unverified: check Meta sources before relying on them.
